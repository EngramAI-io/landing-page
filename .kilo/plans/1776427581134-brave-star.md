## Current State Analysis

### Critical Issues Identified

1. **Identity Crisis**: The landing page has merged content from two distinct projects:
   - **EngramAI/Agent Identity**: Trust layer for AI agents (identity, intent firewall, policy engine)
   - **Sentinel/MCP**: Separate observability product (open-source MCP sidecar)
   
   Components that describe Sentinel but aren't about EngramAI core:
   - `WhatIs.tsx` - Describes Sentinel, not EngramAI
   - `Vision.tsx` - Mentions Sentinel
   - `Security.tsx` - Sentinel security philosophy
   - `Comparison.tsx` - Sentinel vs MCP Inspector
   - `Features.tsx` - Sentinel guarantees
   - `DefenseLayer.tsx` - BOG content

2. **Massive Duplication**: The same concepts repeated across multiple sections:
   - `CoreFeatures.tsx`, `HowItWorks.tsx`, `AgentProtectionPaths.tsx` - All describe EngramAI's core capabilities
   - `ProblemSection.tsx`, `BusinessValue.tsx`, `Benefits.tsx` - All describe the problem/solution
   - `AgentPassport.tsx` repeats identity concepts from `CoreFeatures.tsx`
   - Stats like "100% Detection", "<5ms Latency" appear 3+ times

3. **Hero Section**: Currently has text with a large image TrustDiagram. The `engram-trust-hero-v2.html` visualizes AI Agents → Trust Orchestration → Enterprise Systems with Agent Identity, Ephemeral Access, Intent Firewall, Policy & Audit. User wants this concept "context aware" - integrated into hero design.

4. **Outdated TrustDiagram.tsx**: References `/trust-protocol-diagram.jpg` - this big image should be removed from hero area.

## Key Messaging from agent-identity Docs

### Hero Headline:
"The Trust Layer for Agentic AI"

### Hero Subhead:
"Every action is signed, scoped, verified, and enforced before execution."

### 4-Stage Trust Chain (from engram-trust-hero-v2):
1. **Agent Identity** - Cryptographic DID-style signed attribution
2. **Ephemeral Access** - Task-scoped keys, short TTL, bounded permissions
3. **Intent Firewall** - Intent vs action misalignment detection
4. **Policy & Audit** - Immutable trace lineage, rules enforcement

### 5 Core Pillars:
1. Decentralized Identifiers (DIDs) - Ed25519 cryptographic identity
2. Verifiable Credentials (VCs) - Capability/provenance attestations
3. Token Exchange (RFC 8693) - Bounded delegation with DPoP
4. Dynamic Trust Scoring - Reputation-based security posture
5. Task-Scoped Identity - Ephemeral identities with self-destructing keys

### Compliance Ready:
SOC2, ISO 27001, HIPAA, PCI-DSS, SOX, GLBA
